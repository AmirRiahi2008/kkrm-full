# بک‌اند کانون کارشناسان رسمی دادگستری مازندران

Laravel 13، PHP 8.3+، MySQL 8+ و API نسخه `/api/v1` برای مصرف در Next.js.

ورود داخلی فقط برای داشبورد مدیریت محتوا است؛ مدیر و اعضای مجاز روابط عمومی اخبار، مقاله‌ها و سایر بخش‌ها را مدیریت می‌کنند. ثبت‌نام عمومی وجود ندارد. حساب کارشناسان و ورود عمومی سایت در این بک‌اند پیاده‌سازی نمی‌شود؛ گزینه مربوط در منو به [سامانه مستقل کارشناسان](https://my.kkrm.ir/) لینک دارد. فرانت موجود تغییر نکرده است.

## اجرای محلی با MySQL

PHP 8.3+، Composer 2 و MySQL 8+ لازم‌اند. افزونه‌های `pdo_mysql`، PDO، GD، mbstring، intl، fileinfo، ctype، curl، dom، XML، tokenizer و openssl فعال باشند.

دیتابیس محلی را ایجاد کنید:

```sql
CREATE DATABASE IF NOT EXISTS kkr CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

```bash
cd kkrm-backend
composer install
cp .env.example .env
php artisan key:generate
php artisan migrate --seed
php artisan serve --host=127.0.0.1 --port=8000
```

قبل از migration، مشخصات MySQL خود را در `.env` تنظیم کنید. مقادیر پیش‌فرض محلی:

```dotenv
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=kkr
DB_USERNAME=root
DB_PASSWORD=
```

اگر حساب MySQL رمز دارد، `DB_PASSWORD` را وارد کنید؛ برای محیط واقعی حساب اختصاصی دیتابیس بسازید. تنظیمات بالا به دیتابیس دستگاه شما متصل می‌شوند؛ ساخت و تغییر دیتابیس محلی باید پس از تنظیم این فایل انجام شود. `migrate --seed` جدول‌ها و داده نمونه را می‌سازد. `db:seed` دوباره رکوردهای موجود را تکرار نمی‌کند و رمز حساب‌های موجود را بازنویسی نمی‌کند. برای داده فعلی از `migrate:fresh` استفاده نکنید چون جدول‌ها را حذف می‌کند.

آدرس API: `http://localhost:8000/api/v1`، آدرس فرانت: `http://localhost:3000`. برای هر دو همان نام میزبان `localhost` را استفاده کنید. نیازی به npm یا ساخت فرانت برای اجرای API نیست.

در ویندوز فایل env را دستی کپی کنید. پس از تغییر تنظیمات قبلاً cacheشده، `php artisan optimize:clear` را اجرا کنید.

برای بازیابی رمز، worker را در ترمینال جدا اجرا کنید:

```bash
php artisan queue:work --tries=3 --timeout=60
```

ایمیل محلی در log ثبت می‌شود؛ محیط واقعی به SMTP نیاز دارد.

## ورود داشبورد

ابتدا `GET /sanctum/csrf-cookie`، سپس `POST /api/v1/auth/login` با email/password. کوکی نشست با Sanctum مدیریت می‌شود؛ نمونه مصرف در [docs/NEXTJS.md](docs/NEXTJS.md) قرار دارد.

| نقش | ایمیل | رمز محلی |
|---|---|---|
| مدیر ارشد | admin@example.test | DemoAdmin!2026 |
| مدیر روابط عمومی | relations@example.test | DemoManager!2026 |
| نویسنده | editor@example.test | DemoEditor!2026 |

همه نقش‌ها همان یک مسیر ورود داشبورد را دارند. نویسنده فقط محتوای خودش را به‌صورت پیش‌نویس/درحال‌بررسی مدیریت می‌کند. مدیر روابط عمومی انتشار و دیگر بخش‌ها را مدیریت می‌کند. ایجاد حساب و تغییر نقش فقط برای مدیر ارشد است. کاربران به‌جای حذف غیرفعال می‌شوند. هفت حساب نمونه دیگر (`staff4@example.test` تا `staff10@example.test`) غیرفعال‌اند و رمز تصادفی دارند؛ مدیر ارشد برای استفاده باید آن‌ها را فعال و رمز جدید تعیین کند.

## جستجوی سایت

```text
GET /api/v1/search?q=آزمایشی
GET /api/v1/search?q=آزمایشی&type=news&page=2&per_page=5
```

فقط محتوای منتشرشده و قابل نمایش از سه نوع `news`، `announcement` و `resolution` جستجو می‌شود. عنوان، خلاصه و متن بدون HTML بررسی می‌شوند؛ حروف فارسی/عربی یکسان‌سازی می‌شوند. پاسخ سه گروه با `items`، `total`، `pagination` و `archive_path` دارد. حداقل عبارت دو حرف است؛ اندازه صفحه پیش‌فرض پنج و حداکثر پنجاه است. مقاله‌ها و سایر بخش‌ها در این جستجو وارد نمی‌شوند. جستجوی تخصصی کارشناسان همچنان از endpoint مستقل `experts` انجام می‌شود.

## سیدرها

| منبع | تعداد در نصب تازه |
|---|---|
| هر یک از ۸ نوع مطلب | ۱۰ منتشرشده؛ مجموع ۸۰ + ۲ پیش‌نویس/درحال‌بررسی |
| هر یک از ۸ نوع سند | ۱۰؛ مجموع ۸۰ با حفظ تمام اسناد منوی اصلی |
| کاربران، دسته‌بندی‌ها و برچسب‌ها | هرکدام ۱۰ |
| صفحات، کارشناسان، دوره‌های هیئت و اعضای هیئت | هرکدام ۱۰ |
| قراردادها، رویدادها، پرسش‌ها و اسلایدها | هرکدام ۱۰ |
| حساب‌های بانکی، تعرفه‌ها و پیام‌های تماس | هرکدام ۱۰ |
| گالری‌ها | ۱۰ عکس + ۱۰ ویدئو |
| پیوندها | ۱۰ سامانه + ۱۰ پیوند مفید |
| رسانه‌ها و نسخه‌های نمونه اخبار | هرکدام ۱۰ |
| ساختار اصلی | ۱۱ گروه، ۷۱ رشته و صلاحیت، ۱۱۲ آیتم منو و مسیرهای قدیمی حفظ می‌شوند |

منوها و دسته‌های اصلی به ده مورد کاهش داده نشده‌اند تا هیچ گزینه‌ای حذف نشود. داده‌های نمونه فقط در محیط `local` نصب می‌شوند. در production فقط `SiteStructureSeeder` برای ساخت منوها، لینک‌ها و اطلاعات پایه اجرا شود؛ ساخت حساب واقعی با `php artisan app:create-admin` انجام می‌شود.

متن قوانین، فایل‌ها، کارشناسان، حساب‌های بانکی و تعرفه‌ها نمونه‌اند. حساب‌های بانکی نمونه قابل پرداخت نیستند. تعرفه و حساب نمونه در production از خروجی عمومی پنهان می‌شوند. تعرفه واقعی به مرجع و شماره تأیید مدیر ارشد نیاز دارد؛ موتور محاسبه ادعای پوشش تمام شرایط حقوقی تعرفه رسمی ندارد.

## امنیت و مستندات

CSRF، CORS با مبدا مشخص، نشست رمزگذاری‌شده و کوکی HttpOnly، محدودیت درخواست، bcrypt، لغو نشست پس از تغییر رمز/نقش، Policy/Gate، اعتبارسنجی، پاک‌سازی HTML و دانلود رسانه با بررسی مجوز فعال‌اند. خبر دارای `lock_version` است؛ ویرایش نسخه قدیمی خطای 409 می‌دهد. رمز، مسیر داخلی فایل و خطای داخلی در خروجی عمومی افشا نمی‌شوند. PDF و MP4 در production به ClamAV فعال نیاز دارند.

پروژه فایل، پوشه، تنظیمات یا وابستگی اختصاصی تست ندارد. بررسی‌های عملی تحویل خارج از پروژه انجام شده‌اند. نسخه‌های وابستگی با `composer.lock` ثابت‌اند؛ تنها ابزار توسعه باقی‌مانده Pint برای قالب‌بندی کد است.
